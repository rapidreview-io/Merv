- **The model's identification claim is false as written.** Methods/design says the byte-identical user message and shared format paragraph mean "the contrast isolates extraction guidance." It does not. The control `P0` already contains the same JSON-schema contract (it is not a no-prompt baseline), while `P2` is a **3-shot in-context-learning** prompt containing three full gold JSON objects, and it is 2 602 characters against `P0`'s 519 (2.76× tokens). - **The effect is one field, and inside that field it is a convention effect, not a reading effect.** Company net +18 cells (22 fixed / 4 broken, exact McNemar p = 0.00053); date 0/0; address −2 (p = 0.69); total −1 (p = 1.00). Of the 22 company fixes, **19 are "P0 appended a trailing registration or branch token and P2 dropped it"** (e.g. gold `gerbang alaf restaurants sdn bhd`, P0 `gerbang alaf restaurants sdn bhd (65351-m)`, P2 `gerbang alaf restaurants sdn bhd`) — precisely the convention the exemplars demonstrate: Example 1's OCR contains `FLORISM DE ART (940075-X)` while its "Correct JSON" company is `FLORISM DE ART`.
- **The same induced rule has the opposite sign on the total field and explains the regression.** All 8 total cells where `P0` was right and `P2` wrong are receipts whose OCR glued the currency marker into the target token (gold `rm11.90`, P0 `rm11.90`, P2 `11.90`); the exemplar convention is digits-only. One convention shift produces +19 and −8 cells on the same axis, decided by an OCR tokenization accident spread over five merchant groups. Any theory that reads this as "better extraction" has to explain why the model's reading improved for company format and degraded for currency format.
- **The residual-error argument is contradicted by the project's own data.** `unsupported_gold` is structurally unreachable (gold is reconstructed from the input tokens; I verified 41/41 residual gold strings are literal substrings of the flattened input), 19 of the 41 residual cells carry obvious gold artifacts, and 13 of the 15 residual total cells differ only in numeric/currency formatting. The kit's own cross-check says reconstructed gold matches the canonical SROIE key for only 57% of addresses and 79% of companies; I reproduce 42/68 and 49/68 on the in-kit train rows. One such row scores the model wrong for emitting the canonical name (`billion six enterprise`) because the gold span is truncated to `billion six`.
- **The "not confirmed" verdict survives independent clustered inference of a different kind**, so I do not dissent from the headline: a design-based cluster-robust standard error gives 95% CI ≈ [-0.002, 0.096] (N=80, G=44). But "directional" hides an estimator-dependent picture: the unclustered receipt-level sign test is significant (25 improved / 10 worsened, p = 0.0167), whole-receipt exactness is not (19/10, p = 0.136), and no single cluster's removal pushes the delta below 3 points (min +0.0346 after removing the 15-receipt merchant family). 33 of 44 clusters are singletons, so the wide cluster interval is partly a property of a ratio estimator with random denominators rather than of identified within-family dependence.
- **The "selection" part of the causal claim is untested.** `P2` beat `P1` by one net cell on the 24 development receipts (81 vs 80 of 96, with 7 correctness flips), and `P1` — plain rules, no labelled exemplars — was never run on the holdout. The realised experiment therefore tests "3-shot examples + format vs format alone," a single selection realised once, not "prompt selection improves held-out accuracy."

## The explanatory model, restated

The claim under test (`claim_b5d14a2303a94336a86154cd5feccc4d`): *a prompt selected using development receipts improves held-out four-field receipt accuracy over a plain instruction prompt by ≥ 3 points.* The implicit causal chain is:

development receipts → candidate prompt strings → a selection rule picks the "better" prompt → the selected string, through extraction guidance, makes the model recover field values more accurately on unseen receipts → measured as normalised exact-match cell accuracy against BIO-reconstructed gold.

Two assumptions carry the inference: (a) the treatment is "guidance" and the control is its absence apart from the isolated variable; (b) the scored target measures extraction correctness. Both are contradicted by the retained evidence.

## Findings

**F1 — The treatment is few-shot in-context learning with gold labels, and the contrast is confounded with length.** `P2` embeds three demonstration OCR texts each paired with the full correct JSON; `P0` contains the identical task sentence and the identical output-format paragraph. So the honest description of the contrast is "3 labelled exemplars + format vs format alone". Length differs 519 → 2 602 characters and token cost 486.2 → 1 343.2 (2.763×). The results section concedes the length confound while the methods section asserts isolation; only one of those can stand.

**F2 — The measured effect is a single field, and that field is largely a convention decision.** Company +18 net cells; address −2; total −1; date 0. In the holdout OCR, all 15 receipts of the largest merchant family contain the brand, the legal name and the registration number, so P0's `…(65351-m)` output, P2's legal-name output and P2's occasional `mcdonald's` output are all string-supported by the same input. The score selects one rendering convention. 27 of 80 receipts contain literally, in the input, the "extra" tokens P0 appended.

**F3 — The regressions come from the same convention rule, so the sign of the "effect" is an artifact of target tokenisation.** All 8 P0-right/P2-wrong total cells are currency-glued golds (`rm11.90`, `rm 26.40`, …); the exemplars show digits only. 11 of the 15 residual P2 total errors are the same pattern. This makes "prompting improves extraction" a poor description: the intervention moved the model along a convention axis whose per-cell sign is decided by whether the OCR glued `RM` to the digits.

**F4 — `unsupported_gold = 0` is vacuous, and the residual attribution is falsified at cell level.** Because gold is the concatenation of BIO-tagged input tokens, "gold appears verbatim in the input" cannot fail (41/41). Meanwhile the kit documents that address gold matches the canonical key only 57% of the time, and the paper's own residuals include gold `#2 3 /04/2017` (prediction `3/04/2017`), gold `RM11.90`, gold `(EDAI BUKU NEW ACHEIVERS`, and gold `billion six` where both arms emitted the canonical `billion six enterprise` and were scored wrong. The sentence "no residual error is attributable to BIO/OCR label artifacts in this sample" is therefore not supported by the audit it cites.

**F5 — The plan's stated error-budget hypothesis was already falsified in the exploratory stage.** The methods/results note surprise that address did not dominate; in fact development P0→P2 gained 6 company cells and 4 address cells, so the reversed pattern was visible before the holdout. It also fits a coherent alternative: fields with format anchors present in the text (date patterns, `TOTAL:` lines) are already near ceiling, while the company field is a schema choice among several strings that are all present.

**F6 — Selection is a single noisy realisation.** `P2` won by one net cell over `P1` (81 vs 80 of 96) with 7 correctness flips, and the tie-break cascade (tokens) would have preferred `P1`. Since `P1` was never evaluated on the holdout, the experiment provides no evidence about *rules vs examples*, the mechanism question that would matter most for the decision at hand.

**F7 — Uncertainty reporting hides an estimator-dependent verdict.** Cluster bootstrap [-0.0034, 0.0897] and my independent CRSE [-0.002, 0.096] both include zero → "not confirmed" is defensible. But the receipt-level sign test (25 up / 10 down) is significant at 0.017, and no single-cluster removal drops the delta below 3 points. With 33/44 singleton clusters and one 15-receipt family, the clustered interval mixes within-family dependence with the variance of a ratio estimator with random denominators; the report presents it as the single, final uncertainty statement.

**F8 — Claim wording outruns the evidence.** The claim is a procedure-level statement ("a prompt selected using development receipts improves…") about four-field accuracy in general; the evidence is one realised prompt string, one model, one temperature, one sample per cell, one prompt instance per arm, whose gain is one field's convention alignment concentrated in one merchant family (8 of 22 company fixes and 2 of 4 company breaks are the 15-receipt family; removing it leaves +3.46 points overall).

**F9 — The decision this pilot was meant to inform is under-served by its own framing.** The project asks whether prompting justifies work "before paying for a fine-tuning comparison." The result says prompting is a cheap *schema-convention* lever (large, reliable improvement on a convention field, 2.76× tokens) and not an *extraction-quality* lever (no movement on the fields where information must be read out of noisy OCR). Since `P2` needs labelled exemplars — the same currency fine-tuning would consume — the pilot does not separate "prompt work" from "supervision work."

## Rival explanations that fit the current evidence (ranked)

1. **Convention induction from labelled exemplars (best fit).** Predicts exactly what is observed: big company gain by dropping trailing registration/branch tokens, small currency-marker regression on currency-glued targets, no change in date, weak/negative movement in the noisy address field. Supported by F2, F3 and the exemplar contents.
2. **Prompt length / extra-token priming (not excluded).** 2.763× tokens with one sample per cell; the named length-matched control was never run. This rival is currently indistinguishable from (1) on the retained data.
3. **Selection noise (partially excluded for P2 vs P0, live for the "selection" claim).** P2's adoption rests on a 1-cell margin, but the holdout contrast is P2 vs P0, a 10-cell dev gap, so the realised effect is not obviously a selection accident. What remains untested is the procedure-level claim.
4. **Genuine improved extraction (weakest fit).** It explains only 2 of 22 company fixes, 0 of 3 date changes, and must explain away 8 currency regressions and a −2 address shift.
5. **Broker/serving drift (excluded).** One `system_fingerprint` across all 237 calls, all HTTP 200, 0 retries, frozen prompt hashes, freeze timestamps preceding the first call and the first holdout call; per-receipt inputs byte-identical across arms. I reproduce all of this from the run logs.

## What would discriminate (cheapest first)

1. **Run `P1` (field rules, no labelled examples) against `P0` on the holdout.** Already written, hashed and frozen; one missing arm. If `P1` matches `P2`, the effect is rules/conventions, not exemplars, and no labelled data is needed. Highest information per API call.
2. **Length-matched control**: pad `P0` with neutral text to `P2`'s length (or `P2` with exemplars from a disjoint corpus). Separates convention content from length priming (rival 1 vs 2).
3. **Grade two targets.** Report scored accuracy against reconstructed BIO gold *and* against the canonical key, plus a convention-normalised variant (casefold + punctuation + currency-stripped numerics). This turns C3 from a caveat into a measurement and separates "reads better" from "matches the annotation convention".
4. **Re-run the selection across seeds/subsamples** of the development split to estimate the variance of "the selected prompt" — the only way the procedure-level claim can be tested.
5. **Replicate each cell n times at fixed settings** to bound sampling variance, which the current design leaves unmeasured.

## Limits of this lens and of the evidence

I re-ran no model call and rely on the pinned raw responses; I could not independently verify the broker's temperature/thinking settings (the producer flags the same gap). One sample per cell means model sampling variance is unmeasured, so all intervals understate total uncertainty. The canonical SROIE key is a hand-typed secondary reference, not ground truth — I use it only to show that the scored target is a convention, not that the canonical key is correct. My cluster-bootstrap 97.5th percentile differed from the producer's in the fourth decimal (0.089623 vs 0.089744), presumably a percentile-index convention, so I treat the clustered interval as a range rather than an exact figure. Finally, I verified the exhibit-pointer defect independently: the report names `art_09aad815…51827`/`598c078a…` with 20 result files as "the pinned metrics exhibit", while revision 5 pins `art_f1d4adec…`/`b7d503c7…` with 23 result files — harmless for the science, but it means the report's own metadata paragraph should not be used as the exhibit authority.
