# Legacy UI patterns to carry into the Cordis UI (study, 2026-09-16)

Four Opus readers studied the old React UI (research_state_ui) with the seeded-brain screenshot harnesses and the founder's approved-design notes; a synthesizer merged them. The founder's words: the old UI "has good sandboxing UI, it has consistent patterns for all screens, so that the user is never confused about what to expect, and more".

## Consistency checklist (rules for every new screen)

1. One click on a row means exactly one thing: a row either navigates or toggles a panel open, never both, and every copyable string (ids, oids, endpoints, origins) moves off the row into the panel it opens — the row carries only what a person scans.
2. A table declares its column template once, as one custom property shared by the header and by every line of a row, so the same fact sits at the same x-position down the whole list; a row may take a second line, but no fact ever appears on both lines.
3. Every derived word — a tone, a phrase, a duration, a liveness verdict — comes from one pure, unit-tested module that every view calls; no view composes a status sentence of its own, so desktop, mobile and any future surface cannot disagree about what a row means.
4. A fact the server did not send renders as nothing at all; a fact this record could have and does not renders as the faint em dash; a zero is only ever a measured zero, and no metric is ever drawn at zero because it was unavailable.
5. Every metric slot keeps its position whether or not it has a value — nothing compacts into a neighbour's column — so a column of rows stays comparable at a glance.
6. No unlabelled visual: any bar, gauge, chip or sparkline names its metric beside its value, or it does not ship at all.
7. Time a person acts on is a live countdown at the row's own size in the text colour, it ticks only while something on the page is actually live, it counts down to 0s rather than to a euphemism, and the absolute timestamp lives in the panel rather than the row.
8. Every state of a surface renders the same skeleton in the same order and differs only in which parts are true; a row a state cannot have is dropped rather than rendered empty, and a single action's verb is renamed to match the state it will act on.
9. A destructive control is guarded in proportion to its consequence, the guard names the specific records that will be affected, ordinary forward actions stay one click, and exactly one path per mutation exists on a given screen.
10. Refresh cadence is a function of what is live on screen and stops entirely while the tab is hidden; that rule lives once in the fetch layer, never in a view.
11. Nothing-to-show has a distinct screen per cause — connecting, failed boot, missing record, refresh failed with good data on screen, genuinely empty, filtered to nothing — and each carries its recovery in place; a failed background poll degrades to one line and never blanks data that is still correct.
12. View state lives in the URL: scope in the path, filters and modes in the query string set with replace, a named section in the hash — state a colleague cannot be sent a link to is state the UI should not be holding.
13. Every id and every enum becomes words in exactly one place: an unknown value falls through to readable words in the neutral tone rather than rendering blank or raw, a bare identifier never appears where a name exists, and any sentence about what happens next stays the server's own string, verbatim.
14. A column label is its own sort control carrying aria-sort, the whole row is the activation target with Enter, and created/settled/duration are measured by one shared helper whose tooltip says what the number measures.

## Carry over now

### sbx-row-panel — The row scans, the panel copies — one toggle, one open panel, and its first line is the link out (M)

From: research_state_ui/src/components/SandboxTable.jsx (SandboxRow as role=button/aria-expanded, SandboxDrawerBar, a single `expanded` rowId) with SandboxTerminal.jsx SandboxMeta; mirrored by src/mobile/SandboxCardList.jsx. Screens: fleet-table-dark.png, fleet-drawer-running.png.

To: merv-typescript/packages/ui/web/views/sessions.tsx (the Assignment executions and Runners tables), a RowPanel export beside Table in packages/ui/web/components.tsx, and views/connections.tsx

The Assignment executions table today puts nine cells on one line — agent, work label, role, a three-clause standing, platform, workspace mode, a 12-character headOid, a relative time and a Halt button — and not one of them is a link, so a reader who wants the work item has nowhere to click. Cut the row to the four things a person scans down a column: the agent, the work label, the lease standing, and the lease clock. Make the row body itself a single toggle (role=button, aria-expanded, the row's own background shift when open) and allow exactly one panel open at a time, as both the desktop table and the mobile card list did, because an open panel starts its own live reads. The panel's first line is the link out — the work item by name, with its state beside it — which is the direct translation of the drawer's `EXPERIMENT provicnet_crop_variant_v1 →` and it gives 'where did this run belong' one fixed home instead of a differently-placed link per row. Under that line put the copy targets as KV rows, which components.tsx already exports: instance id, expected revision, runner and host refs, platform with model and effort, the workspace attachment and result oids, and the absolute expiry stamp. Drop any KV row whose fact this lease state cannot have rather than printing it empty. Do the same to views/connections.tsx, where `origin` and `errorCode` are things a person copies into a terminal and are currently mid-row scan noise. Do not use a chevron to mark the toggle — the new contract bans disclosure triangles in normal use, and aria-expanded plus the open row's background is the whole affordance.

Data: Everything needed is already on the sessions ui.read payload (packages/sessions/src/types.ts SessionsProjectStatus): SessionSummary carries id, instanceId, expectedRevision, label, role, status, runnerRef, hostRef, platform{name,harness,model,effort}, createdAt, activatedAt, expiresAt, closedAt, closeReason, outcome, workspaceMode and workspace{attachment,result.stats}. RunnerPresence carries id, machine{hostname,system,architecture}, platforms[], capacity, live, lastSeenAt, desiredVersion/appliedVersion. The one gap for the panel's first line: SessionSummary has no workflow name, so the link target must come from the queue candidate's `workflow` field or be resolved by id prefix until the server ships it.

Founder ruling: sandbox-table-design-approved.md, said "Great job" on bc82d1e4: "Row shows what you scan, drawer shows what you copy — SSH endpoint left the row for the drawer; the drawer's first line is the experiment link ('EXPERIMENT name →') because the row itself only toggles."

### sbx-two-line-row — Two lines per row on one shared grid — identity above, liveness below, nothing repeated (M)

From: research_state_ui/src/components/SandboxTable.jsx (SandboxRow + SandboxLiveStrip) with src/styles/global.css:3145-3300, where --sbxt-cols is declared once and applied to .sbxt-head, .sbxt-row and .sbxt-live alike. Screen: fleet-table-dark.png.

To: merv-typescript/packages/ui/web/components.tsx (Table gains an optional secondary line rendered into the same column template), packages/ui/web/styles.css (one column custom property per table), consumed first by views/sessions.tsx

The legacy fleet table is one grid, not three: the header, the identity line and the liveness line all read the same `--sbxt-cols` custom property, which is why a metric stays at the same x-position for the whole length of the table however tall the rows get. Give Table an optional `subRow` render prop that emits a second tr into the same column template (or one spanning cell plus a sub-grid, as SandboxLiveStrip does with grid-column 4/-1), and move the column widths out of per-cell `width` strings into one property in styles.css per table. Use it first on the Runners table, where a machine's identity (hostname, system, architecture, platforms) and its liveness (presence, capacity, last seen, settings pending) currently fight for one line and the machine cell already smuggles a second line in by hand. Then use it on the lease rows: identity above (agent, work, role, clock, open), liveness below (what state the lease is in and how long it has been there, spanning the left columns with its clock pinned to the right edge of that span). Enforce the no-repeat rule literally — the founder cut a duplicated 'running · 8m' from under '● Running', and the same trap exists here, where session.status would otherwise appear both in the standing cell and in the liveness phrase. Pin any column whose content is a fixed vocabulary to the width of its longest honest string so it never ellipsizes, as the Hardware column did. Below the narrow breakpoint the second line stacks under the first as a card, exactly as SandboxCardList does; it must not become a horizontally scrolling table.

Data: No server change. Runner identity and liveness both arrive on the same RunnerPresence record, and the lease's identity and liveness both arrive on the same SessionSummary, so the second line costs no extra request — which was the property that made the legacy liveness strip affordable.

Founder ruling: sandbox-table-design-approved.md: "Two lines per row on ONE grid (shared --sbxt-cols): identity line … and a liveness line underneath", and "Column content must never repeat between the two lines." Approved at bc82d1e4.

### sbx-liveness — Liveness is behavioural, not lifecycle — one tested module, and silence when the server cannot say (M)

From: research_state_ui/src/utils/fleet.js (fleetActivity → work/fail/idle/quiet, commandStatus, commandGist, hardwareLabel) with src/utils/fleet.test.js, consumed unchanged by SandboxTable.jsx and mobile/SandboxCardList.jsx. Screens: fleet-table-dark.png (running · 9m, idle 23m · exit 0, failed · exit 1 · 12m ago, 'no commands yet').

To: a new pure module beside merv-typescript/packages/ui/web/states.tsx, covered by the existing `npm run test:ui`, called by views/sessions.tsx and views/connections.tsx

The legacy fleet keeps two separate questions apart: 'running' is the lifecycle, 'working' is the behaviour, and only the behavioural answer takes a tone. Port that split as one pure function next to states.tsx — which already has the right instinct that a clause passed as null reads as absent while a clause left out is a fact this record cannot have — turning a runner {live, lastSeenAt, capacity} or a lease {status, activatedAt, expiresAt, closedAt, closeReason, outcome} into a tone plus one composed phrase. Every view calls it; no view re-derives a liveness phrase, which is what stopped the old desktop and mobile surfaces from ever disagreeing about a row. Compose the phrase the way the founder-approved row does — a state word, a middle clause, and an elapsed clock in a fixed order — so 'active · 9m', 'offered · 2m, not taken up', 'closed · halted by operator · 12m ago' line up down the column. Keep the honesty guard verbatim: when the payload omits the keys the phrase needs, return null and render no liveness line at all rather than asserting 'nothing yet', because that is precisely what let the old UI ship ahead of its server without inventing a fact. Be explicit in the module's own doc comment about what it cannot yet say: there is no utilisation or per-box command feed in Cordis, so the tone may distinguish live from stale from closed, and must not pretend to distinguish a lease that is working from one that is idle. Give it table-driven tests as fleet.test.js has, since the whole value of the module is that one table, not a rule scattered across views.

Data: Present on the sessions ui.read: runner.live and lastSeenAt give presence and staleness; session.status with activatedAt and expiresAt gives the lease phase and its clock; closeReason and outcome give the terminal verdict, which views/sessions.tsx already renders through ThreeStates. Absent with no substitute: cpu/mem/gpu/vram utilisation, an idle_since, and any per-row last command — sessions.agentObservation returns AgentToolCall{tool,status,startedAt,durationMs} but only per expanded agent, never on the row payload.

Founder ruling: No ruling on the module itself; the founder approved the row it produces at bc82d1e4, including the command-gist and clock phrasing ("Commands as a gist … clock pinned to the span's right edge").

### sbx-countdown — The lease clock: a live countdown that ticks only while something is live and counts to zero, not to a word (S)

From: research_state_ui/src/components/SandboxTable.jsx (expiresMs/expiresCls with the 10-minute and 2-minute thresholds, fmtDuration(Math.max(0, expiresMs)), '—' when a row cannot have the fact) and src/store/useNow.js, where a falsy interval freezes the clock. Screens: fleet-table-dark.png (6m amber, 21s red), fleet-drawer-running.png (the absolute ISO stamp stays in the drawer).

To: a useNow hook in merv-typescript/packages/ui/web (or beside api.ts), a shared Elapsed/Countdown cell in components.tsx, used by views/sessions.tsx and views/agent-sessions-panel.tsx

views/sessions.tsx declares session.expiresAt in its Session interface and never renders it, and the only place a lease deadline appears anywhere in the new UI is views/agent-sessions-panel.tsx, as an absolute toLocaleString KV — so the one number that decides whether a person intervenes is currently either invisible or unreadable at a glance. Add an Expires cell to the lease rows carrying the remaining time at the row's own type size in the text colour, clearly separated from the platform phrase, with the legacy thresholds: under ten minutes amber, under two minutes red, and a past-due lease counting down to 0s rather than saying 'soon'. Add the matching relative clock to a runner's lastSeenAt so a stale heartbeat reads as a duration rather than a timestamp. Drive both from one useNow hook that takes a falsy interval when nothing on the page is live, so an idle Agents page stops re-rendering every second — the legacy page did exactly this with `useNow(anyLive ? 1000 : 0)`. A row that cannot have the fact (a closed lease) renders the faint em dash, not an empty cell and not a stale countdown. Keep the absolute stamp where the drawer kept it, in the panel's KV, so the row stays scannable and the exact value stays copyable. State plainly in the treatment note that this is information and not yet an action: nothing in packages/sessions exposes a lease extension to the browser, so the countdown must not grow a button it cannot honour.

Data: Present and currently unused: SessionSummary.expiresAt, activatedAt, createdAt, closedAt and RunnerPresence.lastSeenAt all arrive on the sessions ui.read. Missing: SessionSummary carries no hardDeadline (it exists on the internal Session type but not on the summary), and there is no renew or extend endpoint.

Founder ruling: sandbox-table-design-approved.md: "Time you act on reads big: uptime/expiry at the row's own size in the text colour, clearly separated from hardware. No word 'soon' — a past-due lease counts down to 0s in red."

### sbx-confirm — A destructive control guarded in proportion to its consequence, naming what is under it (M)

From: research_state_ui/src/components/TerminalTransitionConfirm.jsx (role=alertdialog, focus trap, Escape, 'This will set X to Y … and close it to all further workflow transitions', 'This action cannot be undone.', btn--danger, busy label) and mobile/SandboxCardList.jsx's inline release confirm, whose escalation line reads '⚠ <experiment> is RUNNING on this sandbox — releasing terminates the VM under it'. Screen: fleet-mobile-release-confirm.png.

To: a ConfirmAction export in merv-typescript/packages/ui/web/components.tsx, used by views/sessions.tsx for the per-lease Halt and for Halt all sessions

There is no confirmation component anywhere in packages/ui/web — a grep for 'confirm' outside review prose finds only mutations.ts's error copy — while views/sessions.tsx ships a per-row Halt and a Halt all sessions button as plain one-click controls whose only warning is a faint paragraph nobody reads at the moment of clicking. Port the desktop grammar, not the mobile gesture: one small ConfirmAction with role=alertdialog, a focus trap, Escape to dismiss, a danger-styled primary control and a busy label while the request is in flight. Its body must name the specific records under the click, which is the whole point of the legacy escalation line: for one lease, the agent by name and the work item it is executing; for Halt all, the live leases listed by work name rather than a count, plus the consequence the current UI hides — halting with no sessionId also disables automatic dispatch. Label the primary control by its consequence rather than with a generic verb, and rename it per state as the legacy header did when it read 'Cancel' while provisioning and 'Release sandbox' while running. Say what does not change, because that is what makes the cost legible: the assignment returns to the queue and no verdict, claim standing or review state is affected. Keep ordinary forward actions — pausing dispatch, enabling dispatch — at one click; the guard is for the irreversible half only. Route the failure path through mutations.ts's existing uncertain-result wording so a halt whose response never arrived says so instead of silently appearing to have worked, and keep exactly one path per mutation on the screen rather than a second, weaker one suppressed by a flag.

Data: Everything the confirm text needs is already on screen: liveSessionCount, session.label, role and agentId with agent names already resolved in the view, runnerRef, dispatch.enabled, and the halt endpoints the view already calls.

Founder ruling: None on the sandbox confirm itself — the founder's fleet review was about row legibility, so treat this as a proposal, not an approved design. It does serve the UI_TRANSLATION item 'sessions-lease', which asks that Halt disclose what stops, what is already recorded and what happens to the science.

### poll-cadence — Poll cadence follows liveness and stops while the tab is hidden — once, in the fetch layer (S)

From: research_state_ui/src/pages/Sandboxes.jsx (3s while any row is running or provisioning, 10s otherwise) and src/components/SandboxTerminal.jsx, whose comment records that without the visibility gate the 3s poll 'keeps the radio awake on a locked phone … a live battery bug on every surface'.

To: merv-typescript/packages/ui/web/api.ts useTool (the refresh scheduler at the `if (!cancelled && options.every)` line), with views/sessions.tsx and views/connections.tsx passing a derived interval

useTool schedules its next refresh unconditionally, and every live view passes a constant: views/sessions.tsx and views/connections.tsx both poll every 4000ms forever, hidden tab or not, which is a battery and server cost the legacy UI explicitly engineered away. Put the visibilitychange gate inside useTool so every caller benefits at once — skip the scheduled refresh while document.visibilityState is 'hidden', and fire one catch-up refresh on return, which is exactly the legacy pattern and is what makes a backgrounded dashboard correct rather than merely quiet. Let `every` accept a value derived from the loaded data so a project with nothing live polls slowly: sessions can compute it from liveSessionCount and runner.live, connections from whether any mount is 'connecting'. Fix the cadence in the view that owns the data rather than adding a second timer anywhere, since centralising fetching in useTool is the one structural advantage the new UI already has over the old one's three separate interval loops. Keep the existing wait-for-response-before-rescheduling behaviour, which the legacy code lacked and which matters more on slow remote storage. Do not port the cursor-accumulated tail: no Cordis tool offers an incremental read, and the contract's never-list rules out log tailing outright, so only the cadence and visibility halves of this pattern carry.

Data: Present: every ui.read response already carries the liveness needed to choose a cadence (liveSessionCount, runner.live, mount.state). Missing: no cursored or incremental read exists on any tool, so byte-level tailing is out of scope by design.

Founder ruling: None.

### stale-not-blank — A failed refresh degrades to one line; it never blanks data that is still correct (S)

From: research_state_ui/src/components/LoadState.jsx (StaleNote: 'Couldn't refresh — showing the last loaded state', with the error kept in the title attribute) and src/components/ErrorBoundary.jsx keyed by pathname in App.jsx. Screens: experiments.png, not-found.png, unknown-project.png.

To: merv-typescript/packages/ui/web/components.tsx (LoadState gains a stale line), views/tasks.tsx, views/experiments.tsx, views/reviews.tsx (remove the `&& !list.error` guards), and app.tsx (a route-keyed error boundary)

api.ts already does the hard half correctly — on a failed poll it keeps the last good data beside the error — but every list view then throws that work away, because tasks.tsx, experiments.tsx and reviews.tsx each render their table only when `visible.length > 0 && !list.error`, so one flaky refresh replaces a correct list with an error page. Invert it: when data is present and an error arrives, render the data and one muted line saying the refresh failed and this is the last loaded state, with the server's message in the line's title, and reserve the full error state for the case where there is nothing good to show. The shell already does exactly this for navigation ('Navigation could not refresh: … Showing the last available views'), so this is making the views consistent with the shell rather than inventing a pattern. Add a route-keyed error boundary in app.tsx so one bad payload blanks a single page instead of the whole application, which the legacy App.jsx got by keying the boundary on pathname. Keep LoadState's typed 403/404/other titles and its optional back link; they are already the right shape. Leave the one-line dev boot hint and the single global sync chip behind — the new UI polls per tool, so one 'synced now' claim for a whole page would be a statement the data cannot support.

Data: No server change. ApiError already carries code, message and HTTP status, and useTool already retains last-good data next to the error.

Founder ruling: None. The adjacent recorded ruling is docs/UI_DESIGN.md principle 3, that explanations live in empty states where they help.

### deliverable-ledger — The deliverable-to-confirmation ledger, with marks only a review can set (M)

Keep the founder's cut of the unlabelled sparkline on every form factor, including the mobile card where it still survives. The provisioning state gets the same row slot the command occupies, so a booting box never goes quiet, and the panel keeps the same skeleton across provisioning, running and terminated with the action's verb renamed to fit ('Cancel' while provisioning, 'Release' while running, gone when terminated).

Blocker: There is no compute-fleet service in Cordis at all — no provider, region, SKU, price, uptime, expiry, utilisation sample or command history exists to project. This waits on a sandboxes package with a row adapter of its own; nothing about it should be approximated from session leases.
