# Remaining Python → TypeScript capabilities

Current source check: 2026-09-16. This list supersedes the historical missing-feature tables in BACKEND_PARITY_AUDIT.md. A component on disk or a focused test does not establish integrated product parity.

## Implemented now

- **Production storage:** native PostgreSQL State, asynchronous explicit transactions and migrations, and immutable S3/R2 Blobs. Real Azure staging checks pass for role isolation, R2 reads/writes, rollback and restart persistence. Normal inline reads remain 2 MB; imported large files have authorized short-lived downloads. See [storage](PRODUCTION_STORAGE.md) and [staging](../deploy/STAGING_2026-09-16.md).

- **Reflections:** five independent lens child workflows, synthesis, independent review and repair. New waves read live research on demand and pause new task/experiment creation while existing work continues. Reflections has no Knowledge dependency; Research supplies optional live-evidence read permissions. Old snapshot-based waves remain supported.
- **Consolidation:** a separate code implementation/review workflow with an explicit experiment decision scope and exact Git proposal review. Code is mandatory inside this optional plugin. Completion explicitly does not advance central Git. Existing report-only work remains supported for compatibility.
- **Living paper:** problem/scope/goals/constraints, ordered literature sections, citation records and revisioned Methods/Results. Experiment and reflection submissions propose paper edits; their scientific reviews accept those edits atomically. Paper is a document store, with no separate writing assignments.
- **Research coordination:** new `research@3` cycles finish after reflection approval when no code changes are selected, or continue through Git consolidation. Research requires only State, Scope and Workflows; Paper, Reflections, Knowledge, Consolidation, Tasks and Experiments are optional. Only actions using a missing provider wait. Existing version-2 cycles retain their original graph and replay behavior.
- **Artifact file upload:** a local CLI convenience sends file bytes through existing artifact.create; the model need not reproduce file contents in its tool arguments.
- **Continuing agents and UI:** stable agent identity across assignments, lease recovery, agent table and live-assignment filter, assignment inspector and durable admitted-tool-call observations. Displayed token counts are payload-size estimates.
- **Plugin boundaries:** Scope owns access policy; External Mounts owns upstream credentials. Experiments/Knowledge optionally use Code. Unloading Code suspends Consolidation without unloading Research, Reflections or non-Git agent work. The interactive DAG reflects these relationships.

The final production-storage regression ran **781 tests: 780 passed, zero failures, one optional external Nisa checkout skip**, with PostgreSQL enabled; deployment tests passed **9/9** and backend/UI checks passed. See [current verification](../VERIFICATION.md). The [earlier living-research acceptance](LIVING_RESEARCH_VERIFICATION.md) records its original architecture and browser checks, not today's final design. Existing task/review loops, current-gate guidance, experiment attempts, context recipes, shared identity/keys, native Runner processes, Git workspace capture and reviewed Code proposals are also implemented. This is local integrated behavior, not full legacy parity or production rollout proof.

## Deliberate boundaries

- OAuth is deferred; key-based access is the current target. Shared identity and Nisa mounting already have implementation and local tests; real shared-provider deployment and per-user upstream integration still require acceptance beyond synthetic authentication/model fixtures.
- Remote compute and heavy storage remain in **merv-sandboxes**, accessed through external mounts. Merv owns its research evidence bytes through the implemented Blobs provider; migration does not copy sandbox-owned datasets into that bucket prefix.
- A new plugin is not implied by each row. Most gaps extend Claims, Knowledge, Code, Sessions or the existing research programs.
- Cross-machine Git object delivery is a TypeScript deployment requirement; Python’s private central repository does not by itself establish a completed cross-machine reference implementation.
- Neither backend automatically proves scientific validity; structural evidence checks and independent review must not be described as an automatic statistics verifier.
- Frozen reflection corpora, standalone paper-writing assignments and mandatory report-only consolidation for new research cycles were deliberately removed. They are not remaining port tasks.

The integrated living-research loop is complete within this scope. The next research correctness gap is applying/publishing reviewed knowledge; central code publication follows its explicit repository-authority requirements. Candidate management and operational conveniences are separate priorities.
