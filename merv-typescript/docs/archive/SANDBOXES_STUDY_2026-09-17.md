**It ships a UI.** `ui/` is a React app built to `ui/dist` and served by the control plane at `/ui` (`control/src/merv_sandboxes/api/ui.py`). Routes: `sandboxes.tsx` (371), `sandbox-detail.tsx` (577), `new-sandbox.tsx` (611), `jobs.tsx` (372), `spend.tsx` (349), `providers.tsx` (302), `settings.tsx` (373), `snapshots.tsx` (59), `login.tsx` (184). Components include `terminal-pane.tsx`, `spend-chart.tsx`, `data-table.tsx`, `lease.tsx`, `state-badge.tsx`, `provider-icon.tsx`. This is the only thing in the repo that is TypeScript.

**API surface.** ~80 HTTP routes under `/v1` (`control/src/merv_sandboxes/api/routes/`: sandboxes, jobs, storage, snapshots, workflows, spend, providers, access, accounts, auth, terminal, internal, system) and **35 MCP tools** over Streamable HTTP at `POST /mcp`, same bearer token (`control/src/merv_sandboxes/mcp_server.py`, 752 lines): `sandbox_{list,get,options,create,delete,renew,events}`, `job_{run,status,read,cancel,list}`, `storage_{upload,resume,complete,manifest,get,list,download,delete,usage}`, `workflow_{submit,get,list,cancel}`, `access_{certificate,gateway}`, `providers_list`, `spend_status`, `usage_report`, `snapshot`. Routes and MCP tools call the same service objects; one error envelope.

**Data model** (`control/src/merv_sandboxes/db/schema.py`, 544 lines, **32 tables**): `sandboxes` (compare-and-set state machine `provisioning → ready → deleting → stopped` + `failed`/`unknown`, `revision`, `operation_id`, `lease_expires_at`, `agent_connected_at`/`agent_seen_at`, `presence_checked_at`, `main_job_id`), `sandbox_events`, `work_items` (durable queue, `SKIP LOCKED`), `certificates`, `sessions`, `jobs`/`job_events`/`job_outputs`/`job_reader_progress`, `snapshots`, `pipelines`/`pipeline_outbox`, `storage_*` (5 tables), `budgets`, `provider_credentials`, `users`, `api_tokens`, and 12 `infra_*` tables (accounts, members, namespaces, subjects, policies, resource limits, compute accounting, adjustments, import records, provider controls, usage gaps).

- **Leases**: `lease_expires_at` on the sandbox row; `lease_seconds` bounded by config; renew re-checks spend. Reaped by the lifecycle worker.
- **Heartbeats**: two kinds. Tunnel sandboxes' `sandboxes-agent` heartbeats via `POST /v1/internal/gateway/agents/heartbeat` → `access.agent_heartbeat()` → `agent_seen_at`; the worker kills a sandbox with no heartbeat for `3 × agent_heartbeat_seconds` (default 30s). Separately, `work_items` have a worker heartbeat (`lifecycle/queue.py:181`).
- **Retention**: job logs roll at 64 MiB/stream (`jobs/retention.py`); storage objects have explicit retention (`PATCH /v1/storage/objects/{id}/retention`); expired leases delete machines.
- **Runs/terminal**: there is no "runs" resource — jobs are the durable run record. Terminal is a **WebSocket**, not MCP: `POST /v1/sandboxes/{id}/terminal` returns a one-time 60s ticket, `WS /v1/sandboxes/{id}/terminal` bridges to SSH through the gateway with a 120s cert for a throwaway key, attaching `tmux new-session -A -s main`.

**Credentials.** Per-user BYOK, verified against the provider before saving, sealed AES-GCM under `~/.sandboxes/vault.key` (`providers/vault.py`, ADR 0005). Nothing reads a key back; **MCP tools cannot save one**. Operators can share a provider from `control.toml`. There is an in-process Ed25519 SSH CA (user CA + host CA) in `access/` with OpenSSH certs parsed/built/verified by hand in `sshcert.py` (441 lines).

**Hatchet.** Used for _pipelines only_, not for sandboxes, jobs or leases. `pipelines/worker.py` defines two Hatchet tasks (`merv-pipeline-advance`, `merv-pipeline` durable task); the local loop only drains a SQL outbox. Config: `hatchet_token`, `hatchet_host_port`, `hatchet_tls_strategy` (`config.py:169-171`). Compose overlay `deploy/docker-compose.hatchet.yml` runs `hatchet-lite:v0.105.16` + its own postgres. Pipelines back the storage-transfer / input-to-artifact workflows (`docs/workflows.md`, `docs/storage.md`).

**Gateway.** sshpiperd (MIT, vendored) + the `sandboxes-router` Go plugin. It decides nothing: for every connection it forwards the presented cert to `POST /v1/internal/gateway/authorize` and pipes the session with the short-lived credential the control plane returns. It also terminates the reverse tunnels from `sandboxes-agent` and records sessions as asciicast. **This is not portable to TypeScript in any cheap way** — it is an SSH proxy in Go with e2e tests (1,266 lines of Go e2e alone).

### `READ_ONLY_SANDBOX_MOUNT.md` — how complete it actually is

It is a **safety proof for exactly one call**, not an integration design. It selects `usage_report` alone, binds it to `https://sandboxes.rapidreview.io/mcp`, and records that on 2026-09-13 one authorized live run delivered one scoped report to a fresh Codex agent. `scripts/live-sandbox-mount.ts` (650 lines) is a one-shot harness with a fetch boundary that refuses every destination but that origin and every tool but `usage_report({})`; `tests/live-sandbox-mount.test.ts` (237 lines, 8 tests) asserts those boundaries offline.

**What it does not have:** no UI row, no view, no tool selection beyond one read tool, no namespace-per-project mapping (each binding pins one `x-sandbox-namespace` header, so one binding per project × actor), no production config path (`render-config.mjs` can't emit a mount), no terminal story (WebSocket, outside MCP), no SSH-certificate flow to agents, no lease/heartbeat surfacing. And it records a **hard blocker**: `workflow_submit`'s advertised input schema "currently uses an unsupported `discriminator` keyword. Importing the entire catalog would fail." That is real — `packages/api/src/schema.ts:75` compiles with Ajv `strict: true` and rejects unknown keywords. Only **3 of 31** discovered schemas were ever compile-checked; 1 of those 3 (`providers_list`) was excluded because it can create a Modal cloud app as a side effect of `health()`.

## RECOMMENDATION

**C, with D1 folded into it, and D3 as a follow-on** — a `packages/sandboxes` Cordis plugin holding a _typed_ client over the existing `/v1` API, owning the `sandbox.*` tool grammar, one UI row and one view; the machine-facing control plane (provisioning, the BYOK vault, the Ed25519 CA, the Go gateway, the terminal) stays exactly where it is, and its React UI is deleted in favour of Merv's. The founder's instinct is right about the half that should be TypeScript and wrong about the half that shouldn't: what is weak in merv-sandboxes is the agent-facing tool grammar (35 raw names, no experiment association) and a separate shadcn console nobody wants to visit — both cheap to rebuild in merv-typescript. What is _strong_ is 11,091 lines of 21 provider adapters, an Ed25519 SSH CA with hand-rolled OpenSSH certificate parsing, a Go SSH proxy with 1,266 lines of e2e tests, 24 migrations and 545 passing tests against a 32-table money-and-machines state machine — none of that is TypeScript-shaped, and re-earning it (option B) is a multi-month project whose failure mode is silently-billing GPU boxes and leaked SSH access. Option A is genuinely cheap and I'd expect it to work for a read-only tile, but it does not survive contact with the operational surface: the design doc itself records `workflow_submit`'s schema failing Merv's strict compiler, `providers_list` creating cloud resources as a side effect of "read", and only 3 of 31 schemas ever checked; on top of that, credential bindings are per-(project, actor), so every source key needs a config row, and the legacy `RemoteSandboxes` existed _precisely_ to narrow 35 tools to 14 and clamp waits at the 30s the service actually honours — a generic mount throws that judgement away. C costs ~1,200–1,900 lines, reuses ~38,000, honours the standing three-layer ruling in `MODULE_BOUNDARIES.md` verbatim ("no cloud SDK and no physical object store is part of Merv"), and if it is wrong the blast radius is one page and one tool namespace while leases keep reaping under service authority.

### The load-bearing field problem

The whole `/sandboxes` payload today is built by `merv/src/merv/brain/infrastructure/sandboxes.py:130–147` (`_snapshot`), called by `for_project` (L287–289) through `views.py:85–86`. **Fields the legacy UI renders that the sandboxes API does not have today:**

- `heartbeat` (`latest`, `series`, `idle_since`, `gpus`) — **gone**. Every `heartbeat` hit in `merv/src` is an agent-session runner. This kills `usageBars`/`usageLead`/`usageTrend`, the live VRAM and GPU-count sources, and the `idle` tone.
- `last_command{command,status,exit_code,started_at,finished_at}` — **gone**; only `last_command_finished_at` survives, inside `sandbox.terminal` (`sandboxes.py:505`).
- `ssh_host` / `ssh_port` / `ssh_user` — **gone**; SSH now arrives as a nested `ssh{host,port,user,certificate,…}` object only on `sandbox.get`/`_facts`, only when a certificate is issued (`sandboxes.py:174–176`), never on the list.
- `sync_dir` / `sandbox_data_dir` / `unsynced_dir` — zero hits in `merv/src`. The retention modal is reading fields that do not exist.
- `sandbox.error` (`SandboxTerminal.jsx:208`) — the row carries `detail`, not `error`.
- `price_usd_per_hour` is on the row and **no legacy surface shows it**.

`fleet.js:31–45` already anticipated this: absent keys mean "this server cannot tell me" and the liveness line renders nothing. In practice that means **the second line of the approved row is silent on production data today**.

Also: `dev_docs/seed_fleet.py` no longer runs against main. It writes a local `sandboxes` table and calls `app.sandbox_storage.record_heartbeat` / `record_command_snapshot` (L186–210, 216–226); `sandbox_storage` has zero hits in `merv/src` and `persistence.py:44` has only `remote_sandbox_links`. `dev_docs/fleet_shot.mjs` is fine — it only needs a URL that renders `.sbxt`.

## 2. Patterns to steal (extending the `sbx-*` items, not repeating them)

The doc already carries `sbx-row-panel`, `sbx-two-line-row`, `sbx-liveness`, `sbx-countdown`, `sbx-confirm`, plus `fleet-surface`, `row-last-command`, `provisioning-narration`, `lease-extension`. These are new.

**sbx-attention-view — a computed "needs you" set, not a status filter.** `merv-sandboxes/ui/src/lib/activity.ts:90–101`: failed, connection lost, lease past due or under 15 min, last job not `succeeded` — each returning _why_ as a string that becomes a column (`routes/sandboxes.tsx:118–128`). Good because the operator's question is never "which are provisioning", it is "which will cost me something if I ignore it". The legacy has no equivalent; its tabs are enum filters (`Sandboxes.jsx:7`). Needs `status`, `expires_at`, and a last-job state. Maps onto: a new `attention()` beside `sandboxLiveness()` in `merv-typescript/packages/ui/web/liveness.ts`, an extra filter in `list-filters.tsx`, and a contribution to the Overview standing line.

**sbx-status-tabs-as-counts — the count line is the filter, with a live marker.** `Sandboxes.jsx:47–75` + `.sbxt-tab-dot`; the service's version adds the Attention tab turning red only when it has rows and is not selected (`routes/sandboxes.tsx:246–267`). Maps onto the existing `OPEN`/`isOpenTask` count-as-filter pattern in `views/tasks.tsx`.

**sbx-lease-fraction — remaining over granted.** `merv-sandboxes/ui/src/components/lease.tsx:8–39` (`LeaseBar`: `duration(remaining) left` / `of duration(total)`, a 1 px track, a pulse under 15 %) and `:42–51` (`LeaseText` for the cell). Fields: `expires_at`, `time_limit`, `requested_at` — **all three are on the brain row today** (`sandboxes.py:143–145`). Maps onto `Countdown` (`components.tsx:182–188`) with one muted second clause; no new component needed.

**sbx-renew-with-undo — the forward verb is one click, and reversible.** `merv-sandboxes/ui/src/lib/app-data.tsx:82–109`: remember the seconds remaining, renew, patch `lease_expires_at` from the response, toast with an Undo that renews _back_ to the remembered value. Maps onto `mutations.ts` plus a plain button in the Act slot.

**sbx-end-reason — why it ended, from the record, never inferred.** `activity.ts:103–131`, a closed `REASONS` table over `sandbox.delete_requested / idle_deleted / failed / vanished / stopped` events, falling through to the server's own string. **Liveness line** — same grid, spanning columns 1–3, leaving the Lease and Cost columns empty:

Default order: attention first, then live, then newest.

**States:** loading → `LoadState` skeleton with `columns={5}` (`components.tsx:453–464`); failed refresh with data → the single "Could not refresh. Showing the state that loaded …" line (`components.tsx:426–432`); failed load → the typed error with its code; empty with no provider → "No compute connected" + link to Settings › Compute; empty fleet → "No sandboxes yet" / "An agent rents one when an experiment needs a machine."; filtered to nothing → "Nothing needs you." (Attention) or "No stopped sandboxes."; a total not yet known → em dash.

**Cadence:** one `ui.read` for the collection, interval derived from the data — 3 s while anything is provisioning or has a job in flight, 15 s while only idle ready boxes sit there, stopped while the tab is hidden.

## 6. Record page, Act-first

Built on `RecordPage` (`merv-typescript/packages/ui/web/components.tsx:359–395`), whose slot order is already `act → content → history → related → details`, and which drops a slot the record has nothing for (L386–391).

**Header.** Back link; kind label with its slate icon; title = the experiment it serves ("Sandbox for provicnet_crop_variant_v1"), or the machine phrase when unattached — never the uid. `standing` = the liveness phrase. `state` = the state word with its dot.

**act — "What happens next"** (the only controls on the page):

1. **Extend** — the non-destructive verb, one click, fixed grant. `sandbox.extend` exists (`merv/src/merv/brain/infrastructure/sandboxes.py:328–345`) but clamps to 1800 s, so only "+30 minutes" is offerable until that cap is raised; it refuses unless the state is `ready` (L334–335), so the disabled control carries the server's own reason as its title. Patch `expires_at` from the response (L344), then a toast with an Undo that re-extends to the previously remaining seconds (`app-data.tsx:82–109`).
2. **Stop / Release** — behind `ConfirmAction` (`components.tsx:196–243`). The guard body names what is under the click: the experiment by name and whether it is running (the legacy escalation line, `SandboxCardList.jsx:162–166`), the machine phrase and its provider, and **what will not change** — retained job logs stay readable (`sandboxes.py:157`), the experiment record, its reviews and its claims are untouched. The verb is renamed per state, as the legacy header did (`SandboxTerminal.jsx:171`): "Cancel provisioning" / "Release the machine" / absent when stopped or deleting. Busy label while in flight; the uncertain-result path through `mutations.ts`. Note the brain's release route always sends `confirm_retained: true` (`surface/transport/api/sandboxes.py:114, 138`) — the browser's guard _is_ the retention gate, which is exactly why it must name the outputs.
3. **Open in the compute console →** — the one link out, to `<service>/ui/sandboxes/<id>`, following the `management_url` pattern already in `providers.py:29`. Terminal, job output, snapshots and provider credentials live there.

Dropped entirely once the box is stopped.

**content — "What it is running".** The job in flight as one sentence (state word with its dot, the command as machine text, its clock), then the last few jobs as a plain hairline-separated list: name, state, exit code when non-zero, when it finished (`components/job-list.tsx:46–74`). No output pane, no tail — an output the record needs is an artifact. If no job feed is proxied, the slot is dropped rather than faked.

**history — "How it got here".** While provisioning, the ladder (requested → created at the provider → bootstrapped over SSH _or_ machine dialled in → ready), each step filled / breathing / hollow (`activity.ts:136–152`, rendered `routes/sandbox-detail.tsx:198–216`). Then the event log as rungs of text, relative time with the absolute in the title. The end reason as the last rung, in the server's own words (`activity.ts:103–131`). Then the **sessions ledger** — kind (tunnel / visit), from where, started, length, outcome, with an open session breathing (`routes/sandbox-detail.tsx:521–565`) — because that is literally the history of who touched the box.

**related.** The experiment by name with its own state; the task above it if there is one; the artifacts this box produced (job `artifact_id` → `artifact.list`). Links with state words, no ids.

**details.** The KV block, last, holding exactly the copy targets — the one place identifiers are legal, as machine text: the offer id and its price, region, image, login user, the SSH endpoint plus `sbx ssh <id>` as one copyable line, the host-key fingerprint with copy, **asked for** beside **got**, the absolute stamps (offered / ready / expires / stopped), alive-for, and the native provider id.

### What has to land server-side before any of this ships

There is **no sandboxes package in Cordis at all** — `grep -rl sandbox merv-typescript/packages` returns only three READMEs and `runner/src/profiles.ts`. So this waits on a package with a `ui.ts` row adapter. Beyond that, ordered by how much they unlock:

1. `plugin` and `cost_so_far` on the row projection — unlocks the correct provider mark and the Cost column. Both already exist on the service's `Sandbox` (`merv-sandboxes/ui/src/lib/api.ts:63–64, 86`); `_snapshot` simply drops them.
2. `resources.gpu_count` and `gpu_memory_mb` — unlocks an honest hardware phrase and deletes `NOMINAL_VRAM_GB` outright. Also on the service already (`api.ts:5–12`).
3. A last-job summary per row (`{name, state, command, exit_code, started_at, finished_at}`) — unlocks the liveness line's verdict and Attention's "last job failed" clause. The service computes this from one namespace-wide jobs poll (`activity.ts:8–17`); the brain would proxy `GET /v1/jobs?sandbox_id=…` once per project read.
4. An events route — unlocks the provisioning ladder and the end reason.
5. A sessions route — unlocks the sessions ledger.
6. Raising `sandbox.extend`'s 1800-second cap, if the founder wants the service's 1 h / 4 h / 24 h grants.

None of it involves resurrecting the heartbeat sweep: utilisation is not measured anywhere in the current stack, and the gauges should stay cut.
