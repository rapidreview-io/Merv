# UI overhaul and acceptance fixture

Implemented September 16, 2026, with source generated by `claude-fable-5` and locally reviewed, integrated and verified. See [Fable provenance and integration notes](reviews/ui-overhaul-fable-20260916.md). The retained local preview uses synthetic acceptance data.

## What changed

- A project Overview replaces the first registered plugin as the landing page. Current research guidance, experiments, tasks, reviews, agents and claims appear only while their corresponding views are registered.
- Navigation groups registered views into Research, Work, Operations and Activity. Unknown plugin views retain their declared group; routes remain owned by the server.
- A shared warm paper/ink design system, optional dark theme, responsive navigation overlay, keyboard focus handling and readable secondary text apply across the existing pages.
- Tasks, experiments and reviews have shared search/state controls, result counts, explicit no-match states and evidence-first details.
- Agent sessions open on continuing agent identities and current assignments. Operations contains runners/dispatch controls. The detail panel distinguishes current-assignment tool activity from history and labels payload token estimates clearly.
- The project chooser retains searchable full IDs for duplicate names and puts account administration in disclosures.

No backend service, authentication contract, mutation receipt, plugin dependency or npm dependency was added by this UI wave. Historical records remain read-only.

## Start a fresh preview

From `merv-typescript`:

```sh
node --import tsx scripts/ui-overhaul-demo.ts
```

The script creates a new private `/private/tmp/merv-ui-overhaul-*` directory and starts the real local backend on an available loopback port. Set `PORT` to request a particular port. It prints only the URL, directory, private credential-file path and aggregate coverage.

For editing the UI with Vite, use the reported API address:

```sh
MERV_API=http://127.0.0.1:58905 PORT=5181 npm run dev --workspace @merv/ui -- --host 127.0.0.1
```

The fixture allows the exact Vite origin `http://127.0.0.1:5181` in addition to any configured origins; it remains bound to loopback. The existing built UI is also served at the reported API's `/ui/` path. Rebuild the UI or use Vite to see source changes.

## Verification and limits

Backend typecheck passed for the fixture implementation. The exact Vite-origin configuration was then verified through the proxy; earlier temporary data is retained, but this restart issued fresh synthetic tokens. Real local HTTP checks confirmed operator and reader account access, five versus three visible projects, six main-project tasks, a live session, three agent rows, archived pagination (20 rows plus a next cursor), and 403 responses for a reader write and access to a non-member project. Built UI returned 200.

All project text and reported results are invented UI fixture data. No model ran experiments, no external service was called, and no production data was read or changed. Tool-token statistics are payload estimates, not model billing. The archive fixture covers records and navigation, not historical file-download retention cases. There is no active Git runner, external mount or continuous agent generation.

Synthetic account tokens expire after 12 hours. The agent's hard assignment deadline is 24 hours; its heartbeat stops if the assignment becomes unavailable. Restart the fixture to reset state and credentials. This fixture uses SQLite/local files; production PostgreSQL/R2 behavior is covered by the separate storage acceptance work.
