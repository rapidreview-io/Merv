## Package decisions

Tool, API and UI adapters remain independently disposable; joining them to a domain service would make optional presentation or transport control that service's lifetime.

## Alternatives examined and rejected

- **Replace Pi hosts with a shared or one-turn pool.** Current/next/draining states serve deadline rollover and claimed-turn draining, not merely the machine picker. The human resource picker and configured agent moves are real capabilities. A pool would still need tenant isolation, epochs, resource limits, checkpoints and uncertain-write handling. Local synthetic measurements showed a meaningful warm/cold SDK difference but did not establish provider latency or production capacity. This is a separate product redesign, not proven removable machinery.
- **Delete legacy managed compute because observed jobs are terminal.** Current task and experiment creation still selects managed compute when native delegation is not connected. This is an active new-work fallback, independently of the always-on Code Git policy. Deleting it would change what an unconnected project can run.
- **Delete runner-local Git and direct GitHub support.** Current runner configuration, documentation and driver-less pinned workflow policies still reach these paths. Private local ledgers can hold unsettled captures/publications. Idle Main records cannot prove those ledgers are empty. No implicit migration or loss of that documented capability was made.
- **Remove the HF raw-token transition early.** The current runner uses scoped proxy access, but the documented compatibility cutoff is October 8. This review does not shorten that live transition or remove the broker's necessary private upstream resolver.
- **Collapse authorization, storage and transport adapters.** Repeated-looking checks often occur across asynchronous authority changes or different transaction/credential boundaries. They stay unless equivalence is demonstrated. Code filesystem/SQL admission likewise needs its durable journal because those two stores cannot commit atomically.
- **Replace the existing quarantine marker with another state field.** The reserved internal reason prefix distinguishes derived quarantine from an operator decision. Operator collisions are rejected, and release clears derived quarantine and recomputes remaining roots transactionally. A new column would add a historical migration and compatibility rules without removing those lineage operations; no behavior defect was established in this review.
- **Remove text-baseline project-context updates.** Revision-based updates are preferable for detecting intervening edits, but text-baseline updates remain a documented public contract with current callers and replay receipts. Both modes share the same authority and write transaction. Removing a supported input is an API retirement, not dead-code removal.
- **Erase published versions and migrations.** Recipe construction can be simplified while its exported objects remain identical. Published SQL and older supported workflow contracts cannot be treated as dead code merely because current creation selects newer versions.

## Verification

The four deployed batches (PR31–34) received independent source review, targeted PostgreSQL/UI/lifecycle checks, exact-head CI and production verification. The final cleanup has independent source review, 58 focused contract/session checks, 68 UI/composition checks and byte-identical normal UI build verification; its exact-head CI and production gates must pass before it is declared deployed. Batch four's local suite passed 2,985 tests with one skip and no failures. Its deployed-image acceptance exercised managed Git without GitHub, delivery/review replay, agent continuity, private artifact download, reflection and restart persistence against isolated real PostgreSQL and object storage. The production audit confirmed the exact image, unchanged migration hashes, all 46,889 archive records and the retained recovery snapshot.

Release identities are recorded in [the production release ledger](../deploy/RELEASES.md). Audit working evidence includes per-file hashes and read ranges, rejected candidate rationale, test outputs and production receipts; inventories alone are not counted as full reads. No claim that every future optimization is exhausted follows from this review.
