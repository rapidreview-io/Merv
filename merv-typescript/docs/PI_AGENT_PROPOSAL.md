# Optional Pi — later read-only pilot

Implementation tracking: [read-only Pi candidate status](PI_IMPLEMENTATION_STATUS.md). The proposal below remains the acceptance contract; candidate code is not proof of deployment.

**Evidence gate (acceptance-owner decision 2026-09-23T23:04Z).** Complete Merv-controlled isolation, credential protection, capture and canary scans remain mandatory. Enumerate and scan all available Cloudflare logs with source/time/pagination/sampling/truncation checks, while explicitly recording provider-internal/platform-generated visibility limits. Do not demand impossible proof of zero inaccessible provider logs or claim provider-complete coverage. Independent review of the actual evidence and Gates A/B precedes acceptance; a clean scanner result is not acceptance. On2026-09-24 the owner explicitly authorized immediate Pi API/UI enablement for all existing user projects despite unfinished acceptance and the disclosed credential incident. This supersedes the earlier enablement prerequisite, not the evidence requirements or unfinished acceptance status.

Replaces the broader initial Pi plan; deployed to production on 2026-09-24 without completed acceptance (see status). [Joint sequence](FLEET_PI_PROPOSAL.md).

**Product boundary.** Agent sidebar opens a conversation, never a synthetic task. Sending a message requests Fleet capacity. Pi hard-depends on Fleet; external clients depend on neither. One package with server/API/UI/worker entries; only sandbox worker imports Pi SDK. Verify upstream package/tarball before pinning. Disable ambient extensions, credentials and resource discovery; explicitly configure tools/settings.

**Pilot scope.** One active turn per conversation, one machine per person per project (shared by that person's conversations there, up to the machine's turn slots), one model/provider. Audited native read tools only; no shell, arbitrary filesystem, mounted remote tools, mutations, task creation, approval system or Pi assignment profile. Those are later work.

Before pilot implementation choose one provider credential path. Prefer short-lived provider-scoped credentials if the selected provider supports them; otherwise require a narrow authenticated streaming relay with model/size/concurrency limits. This is an explicit Pi prerequisite, not Fleet work. No silent long-lived provider-key fallback or general gateway framework.

**State versus stream.** Two tables initially: conversations (ownership/revision/runtime binding/checkpoint pointer) and commands/outcomes (idempotency/payload digest/canonical messages/tool outcomes/status). Existing artifact storage holds full Pi checkpoints. No durable token-event or acknowledgement-history tables.

Token deltas/progress use bounded memory buffers and SSE outside State. Reconnect returns canonical snapshot plus available transient tail. Server restart may lose the tail, which the UI replaces with canonical state. Persist commands, meaningful turn transitions, final messages/outcomes and checkpoint pointers only; never partial text/token/transport-ack writes. Batch read-only outcomes at safe boundaries. Future mutations need their own durable intent, independent of streaming.

Commit accepted command plus Fleet request together. Bind each turn to its person's host machine with a host-revision CAS. Stable command IDs deduplicate delivery; ambiguous applied prompts become interrupted, not blindly replayed. Checkpoint Pi's full session tree/active leaf to immutable artifacts, verify digest, then CAS the pointer. Preserve previous checkpoint. Saving failure must not erase a real result. Idle release waits for retention. Stop fences new operations and aborts; it cannot roll back completed effects.

**Read-only authority gate.** Proposed conversation grant binds source/project/conversation/epoch, tool allowlist, argument constraints and expiry bounded by source/turn/runtime. It is not a fake Session and must not replace ToolRegistry's singleton session policy. Add an explicit conversation-authority hook alongside existing authority resolution. ToolRegistry recognizes its caller type, requires the provider, filters discovery and checks exact admission. Recheck source/epoch/expiry after asynchronous admission and after snapshot reads before returning results. Missing provider fails closed. Scope retains membership/source/grant resolution; ToolRegistry owns tool admission. Audit read handlers for actual effects; annotations alone are insufficient.

**Before enabling any writes.** Separate gate: extend the native authorization path at Scope.require(caller, permission, tx) to validate conversation authority using the same write transaction. Registry supplies a trusted invocation descriptor containing tool name and canonical argument digest, never accepted from user JSON. Provider checks current source revision, epoch/expiry and exact constraints; native operation also authorizes its actual target. Audit each enabled handler to prove this occurs inside its write transaction, and deny unsupported tools. Pre-dispatch checks alone are insufficient. Do not wrap network IO in a global State transaction as a shortcut.

Exact hook/types require focused review before writes. Race tests revoke membership/grant or cancel the turn between registry admission and native write and must prevent commit. Mounted effects require equivalent admission immediately before dispatch plus idempotency/reconciliation; defer them. No nested-delegation weakening, service-actor substitution (except the capacity-only host renting below) or broad user key. Until this gate passes, create tasks through existing external clients.

**Exception: capacity-only host renting (founder, 2026-09-24).** One Pi host service identity, a reader key in one operator-owned Pi host project, rents every Pi machine, so a project needs no Sandboxes connection for Pi. It substitutes for the person only in renting capacity. Every data read the agent makes still runs as the person, per turn, with the person's current permissions in that project; the host identity is never a data caller. A machine other than the default follows the person's own authority: only when that project has its own Sandboxes connection and the person holds at least write there, and the agent may move only where its person could.

**UI/tests.** Show waiting (no machine yet, queued for capacity), starting (a machine is being prepared), working (the model is answering), saving (writing the checkpoint), interrupted, and unavailable (the project cannot run the agent at all), with optional Fleet detail links. Disabled compiled UI may retain an inert renderer; optional distributions omit its build entry. Pi SDK never enters browser/main server execution. Test real read query, reconnect, eviction/restore, revocation, duplicate commands, stale worker and cancel. Instrument write counts: more tokens must not mean proportionally more State transactions. Measure dispatch/review latency alongside streaming. No multi-user fairness, new approval platform or metering release phase until users demonstrate the need.
