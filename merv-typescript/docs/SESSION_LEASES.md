Continuing agents now have a stable identity and connection above these execution leases. See [Agent continuity](AGENT_CONTINUITY.md). Existing `sessionId` references below identify assignment executions.

Sessions gives an agent a credential for one workflow instance and revision.
Workflows still owns the current gate, blockers, next action, assignment recipe
and fixed tool policy. Tasks and Reviews own their work and claim records.
The session service connects those contracts to an expiring credential; it does
not contain task-specific branching or launch agent processes.

## Source authority and worker identity

Each execution uses its agent’s credentialless Scope actor. Continuing agents reuse that actor across assignments; automatically launched single-assignment agents receive a fresh actor. The source that authorized it
is recorded separately: an exact actor credential, a verified human and membership
epoch, or an exact user-owned key and membership epoch.

| Identity               | Purpose                                                               |
| ---------------------- | --------------------------------------------------------------------- |
| Source human/key/actor | Authorizes the lease and its control-plane operations.                |
| Worker actor           | Attributes artifacts, checkpoints, claims and verdicts to this agent. |
| Session secret         | Authenticates this lease on MCP. Only its digest is stored.           |
| Invocation             | A server-created execution frame for one admitted tool call.          |

Two independently leased agents under the **same human account or machine key**
can produce and review. The producing worker cannot review its own output.
Creating another context window inside the same lease does not create a new
independent reviewer. This is agent independence, not a requirement for two humans.

A worker cannot become an operator, receive an ordinary actor credential or
delegate another lease. Retiring an agent never revokes its source human or key. Closing an assignment retires only nonpersistent agents.
Domain events retain the worker and nonsecret session identity; the lease retains
its immutable source provenance.

Human delegation is checked against the captured live membership epoch rather
than the short lifetime of the login JWT that authorized issuance. A key or actor
credential remains tied to the exact original credential and its expiry. A rotated
replacement does not revive old leases. Membership removal or a role change
invalidates the captured epoch, including after the user rejoins.

Scope tool policy and External Mounts use the verified source to resolve exact remote grants and
upstream credentials. That does not change the worker identity recorded by domain
operations, and does not bypass the session's own fixed tool policy.

## Offer, activate and close

An authenticated source offers a lease against an expected workflow revision.
The offer transaction reserves the domain ownership handle, resolves its final
reference IDs and freezes the assignment. A reviewer receives its claim before
the assignment is frozen. An ordinary account can preview an assignment without
obtaining this ownership or credential.

Only one offered or active lease may own a given project, instance and revision.
Idempotency is scoped to authenticated source authority, not just a caller-supplied
runner label. Changed inputs conflict; replaying an old receipt never revives it.
The secret can be generated by the authorized caller so a lost response can be
retried without storing recoverable secret text on the server.

Offering or attaching a workspace does not start work. First accepted MCP use
checks source authority, expiry, current workflow facts and ownership **before**
recording activation and the first-start event. Later checks use metadata; they
do not rebuild prompts or fetch artifact bytes while admitting a request.

The default offer lifetime is five minutes, the active sliding lifetime
four hours, and the hard deadline twenty-four hours, capped at seven days.
Heartbeat renews an active, unexpired lease only. Release, expiry and lost source
authority close the execution permanently. Continuing agents remain registered unless their source authority is lost or they are explicitly retired.

Closed work leaves durable events for the responsible domain plugin to release
the exact ownership handle. Cleanup can wait while that plugin is unavailable.
A successor execution receives a new ownership handle; an explicitly continuing agent retains its worker identity, while logical task ownership,
evidence, verdicts, checkpoints and start history remain available.

## Enforced execution

The session bearer is MCP-only. It cannot authenticate ordinary HTTP tool routes,
account administration or session control. A session's Merv project is fixed;
request headers and native tool project envelopes must agree. A mounted tool's
own argument named `projectId` retains its upstream meaning.

The tool registry uses one effective policy for discovery and dispatch. Fixed
bindings are checked before parsing, after parsing and before invoking the
handler. Mounted dispatch repeats the check after asynchronous connection setup
and resolves current source credentials immediately before sending upstream.

Native writes recheck session status and source authority inside the writer
transaction. Node revision and ownership admission is memoized only within the
same transaction and server-created invocation: a legitimate transition may
hydrate its result after advancing the revision. Source and lease-status checks
are never skipped, and a later transaction cannot reuse that admission.

Input references are pinned at offer time. Artifact authority may subsequently
grow with outputs authored by this exact worker. Checkpoint attachments are not
an unrestricted way to grant file access. Composite context must obey the same
boundary; later checkpoints from another actor cannot silently add document bytes
to a running session's context.

Durable leases can survive a server restart only after current source, declaration,
reference and ownership checks succeed. Runtime registration generations separately
fence captured in-flight calls after plugin withdrawal and replacement. Missing
providers fail closed; restart does not silently authorize a changed policy.

## Automatic dispatch and project controls

The [runner control plane](RUNNER_CONTROL_PLANE.md) adds server-selected automatic leases, source-bound runner presence/capacity, desired settings and project-authorized status/pause/halt. The optional Sessions UI uses sanitized project metadata. Exact-source lease detail/control remains separate from operator project inspection.

Release can carry a bounded process outcome (`completed`, `host_failed`, `launch_failed`, `workspace_failed` or `crash_loop`) separately from its explanatory reason. Automatic dispatch uses canonical outcomes for retry backoff; a freeform note cannot become scheduling policy.

## Remaining work

This slice does not implement runner processes, workspace provisioning, durable
process launch/reconciliation or branch publication. Those consume the session
control plane after it is integrated and verified. Full experiment/reflection

## HTTP control and configuration

The `sessions` provider depends on State, Scope, Workflows and Domain Events. The small `sessions-api` adapter depends only on Sessions and API.
Neither exposes an agent tool. A normal source credential controls these routes;
use `X-Merv-Project-Id` when project selection is required.

| Route                          | Input / result                                                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `POST /sessions/offer`         | `instanceId`, `expectedRevision`, `runnerId`, `requestId`, `secret`, optional `hardDeadlineSeconds`; returns `{session}`. |
| `GET /sessions`                | Returns `{sessions}` belonging to this exact source authority.                                                            |
| `GET /sessions/:id`            | Returns `{session}` after checking source ownership.                                                                      |
| `POST /sessions/:id/attach`    | `runnerId`, immutable `hostRef`; returns `{session}`.                                                                     |
| `POST /sessions/:id/heartbeat` | `runnerId`; returns `{session}`.                                                                                          |
| `POST /sessions/:id/release`   | `runnerId`, optional `reason`; returns `{session}`.                                                                       |

Generate `secret` as `ms_` followed by 32 random bytes encoded as unpadded base64url
(43 characters). Keep it out of prompts, files, URLs and logs. Supply it as the
MCP bearer. The server never returns or stores its plaintext. Each frozen
assignment, policy and reference packet is bounded at 64 KiB. This is an admission
limit, not a transport upload limit.

Optional Sessions configuration is `sweepIntervalMs` (100–60000; default 1000).
Offer commits expired-predecessor closure and drains durable cleanup before
starting a fresh acquisition transaction. A failing cleanup handler cannot roll
back worker retirement or partially commit domain cleanup.

Run `npm run test:sessions` for deterministic coverage. The separate
`npm run test:live:sessions -- /absolute/new/run-directory` launches two real
Codex agents against synthetic local data; it requires model access and local
listeners. It is an acceptance harness, not the production runner.
